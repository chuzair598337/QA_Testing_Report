# Adding a new report

This repo is a static site — no build step, no backend. Publishing a new
report means: fill the template, drop it in, list it.

## 1. Get a filled report

Reports are generated by the `generate-qa-test-report` skill in the
`siloss_mobile_rn` project (Claude Code). That skill:

- always re-reads the canonical template before writing anything
- copies it into a new file
- fills in only `<title>`, `#doc-title`, and the `DATA` array

Point it at **this repo's** template
(`reports/template/qa-testing-report-template.html`) instead of the
`siloss_mobile_rn` copy when you want the result to land here directly, or
generate it in `siloss_mobile_rn` and copy the finished file over — either
way the two templates should be kept in sync (see below).

## 2. Drop the file in

Save the finished report as:

```
reports/testcases/qa-<kebab-scope>-YYYY-MM-DD.html
```

e.g. `reports/testcases/qa-onboarding-freelancer-2026-08-23.html`. Never
overwrite an existing report file — append `-2`, `-3`, … if the name
collides.

## 3. Add it to the manifest

Append one entry to `reports.json` (flat array, no nesting):

```json
{
  "title": "Onboarding — Freelancer",
  "path": "reports/testcases/qa-onboarding-freelancer-2026-08-23.html",
  "date": "2026-08-23",
  "scope": "Sign-up, MFA, Plaid link, subscription, completion"
}
```

- `title` — shown as the card heading on the index page.
- `path` — relative path from repo root to the report file.
- `date` — `YYYY-MM-DD`, used for sort order (newest first) and the date
  badge.
- `scope` — optional one-line description shown under the title.

The index page (`index.html`) reads this file at load time and renders one
card per entry — no HTML editing needed to publish a new report.

## 4. Commit and push

```bash
git add reports/testcases/<file>.html reports.json
git commit -m "Add QA report: <scope>"
git push
```

If GitHub Pages is enabled on this repo, the new report and its index card
go live at the Pages URL a minute or two after the push.

## Keeping the template in sync

`reports/template/qa-testing-report-template.html` here and
`DOCS/Testing/reports/template/qa-testing-report-template.html` in
`siloss_mobile_rn` are two copies of the same living template. When one gets
a feature update (new UI, new DATA field, etc.), port the change to the
other manually — there's no automated sync between the two repos.
